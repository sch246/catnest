# 02 · 已物化数据流契约（仅留 Why 与死亡边界）

> 具体实现细节已物化于 `catnest_lib/` 与 `probes/`，日常配方不加载本文件，仅在修改数据流机制自身时读取。

### [D1] 原子二分防假穿透（Why）
- **性质**：`[事实]`
- **断言**：把设计取舍（`[意图]`）与可证伪世界状态（`[事实]`）混写，必然诱发用格式检查冒充语义验证的假穿透。
- **锚点**：`probes/probe_canon_hygiene.py`
- **死亡条件**：该二分法在实际写作中造成持续分类摩擦、导致作者绕开 `canon/` 时。
- **别名**：原子格式, 意图与事实分离, 假穿透, 死亡条件, 九命

### [D2] 猫须探针与作用域过期（Why）
- **性质**：`[事实]`
- **断言**：静态文本标签不会随代码提交失效，全仓无差别过期又会制造误报风暴；行为探针与带路径作用域的实测锚点必须在变异时真能 FAIL（`check --mutate`）。
- **锚点**：`probes/probe_cli_contract.py`
- **死亡条件**：探针运行耗时超过 30 秒被跳过，或 `_state/suspect.md` 持续产生无人处理的误报噪音。
- **别名**：猫须, 行为探针, suspect清单, 误报风暴, 漏穿透, 实车过期, 变异测试

### [D3] 水下小岛召回与真实采纳率（Why）
- **性质**：`[事实]`
- **断言**：检索本身不是采纳；只有后续真正被 `touch` 或 `assemble` 装入运行才算有效召回，久未触碰的 `open/` 沉水进 `logs/` 而不删。
- **锚点**：`probes/probe_open_and_recall.py`, `probes/probe_cli_contract.py`
- **死亡条件**：累计 ≥20 次真实 `recall` 后实际采纳率低于 40%（直接替换检索机制，不加权重硬救）。
- **别名**：水下小岛, ACT-R, 沉水, 关联去重, 补别名, 呼噜, 采纳率, BM25

### [D4] 否证记录：零服务器与禁复述代码
- **性质**：`[意图]`
- **断言**：不建常驻编排服务器或重型看板；`canon/` 不复述代码已能自明的实现细节，避免静态架构文档在重构后滞后于源码形成隐性误导。
- **锚点**：`logs/2026-11-20-genesis.md#R3,#R7`（无机器检验）
- **死亡条件**：用户 `Supersedes`，或跨异地主机高频实时并发写同一猫窝导致 Git 冲突无法承受。
- **别名**：零服务器, 文档漂移, 否证负经验, 文件系统即库
