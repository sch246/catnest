# 2026-11-20 · catnest 创世原话、对撞与实证记录

> 只追加不可变事件底库（Layer 0）。记录本工作流诞生时的核心原话、多模型三轮碰撞的否证结论，以及生产实测参考。

## #R1 核心痛点与张力哲学
- 痛点原话：“我的想法和修正是一直在有的，它直接去实现是最差的，整理后变成 spec 和 ticket 不能处理不断来的想法和旧意图还有现实的交互和作用。”
- 张力哲学（源自 `# 2026-10` 笔记）：
  - 工具的价值在于处理张力（顾此失彼），逃避张力的方案总是简单却无用；软件工程的张力在于模糊意图与现实约束的势差。
  - 长期记忆核心在于可信穷尽，只有处于更新能力内的缓存才是可控的。
  - 决策能力守恒，决策空间也守恒；上层为下层服务，理性为感性服务，显意识为潜意识服务。
  - 规矩越复杂，钻空子的利益越大；成为了目标的指标不是好指标。

## #R2 95% 噪音实测与旧方案缺口（工业机器人复杂项目实证）
- 一个复杂多仓机器人系统的全部现行核心真相 `canon/` 仅 189 行、关键溯源日志仅 96 行、总控 `boot.md` 仅 85 行；真正撑爆上下文导致失智的是子代理直接翻了 639 个原始文件。
- 实测软劝告拦不住 LLM 惯性翻文件，但硬规则闸门又会诱发规矩势差陷阱。

## #R3 / #R4 前两轮对抗碰撞（核心否证）
- **否证 1（行数上限与严密规矩）**：150 行封顶、硬白名单、写前四选一都是“没有死亡条件的缓存”，当体检指标可以，当闸门必然变成被优化的目标；硬压行数等于无记录有损压缩，最先丢掉的是最贵的负经验。
- **否证 2（人工翻看的 `00-open`）**：没有活跃度衰减与自动碰撞的 `00-open` 只是换了名字的 Ticket 堆。
- **否证 3（无锚点 `[实测]`）**：代码变更不会让文本标签失效，过期真相看起来最权威。
- **确立**：原子 = `断言 + 锚点 + 死亡条件`；缓存上限由反射层复核能力决定，不由行数决定。

## #R5 第三轮碰撞（代码位置与组织减法）
- 锚点锚在可执行行为上（`probes/`），不死锚实现文件；漏穿透补锚，频繁误报说明对象易变应踢出 `canon`。
- 触手碰到另一条意图碎片也算接触，张力本身就是触手的方向；没人碰的自然沉水入 `logs` 不删。
- 代码分“必扔的探针代码”与“河床代码”；`canon` 的置信度决定代码浇筑的可塑层次；河床代码 + 探针 = 可执行 `canon`，文本只留代码说不出来的意图、原因与负经验。
- **猫是上下文的组装配方，不是实体。真正存在的只有原子、反射和一个 ego。**

## #R6 自维护公理与物化边界
- “好的工作流应该维护自己的结构与设计，用跑出来的经验优化自身——维护自己本身就是运行自己的经验。”
- 对冻结权重的 LLM，“内化”只能是**物化**（压进模板、探针、限流与钩子结构，物化完撤出日常上下文）；同时不依赖虚伪自报或自动自改死循环，而是靠被动痕迹取证配合人工授权复盘（`retro`）演进。
