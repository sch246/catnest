# 文档原子的生长、局部性与反假闭合参考

当复杂度超过单次会话上下文，需要用持久文档维持**局部性**（单次工作串起的原子不超过可承载范围）与**传递性**（事实或边界变化能抵达受影响的局部）时，参考以下准则。若仓库已有知识索引或设计结构，沿其权威入口演进，不另起炉灶。

## 从整体底座到局部原子的自然裂变

不要在尚未接触现实前，按历史项目的目录模板预建多个空方案。预先切格子容易诱使后续工作把排他的猜测塞进空文件。

1. **低水位期**：刚收到意图、整体耦合尚未摸清时，先维护一份整体认知文档，锚定原始意图与目标、已核实的现实地面、显式张力，以及仍待接触现实的问题面。
2. **涨潮期**：当需要深入不同代码域、数据或交互面并行取证，且细节会撑大协调上下文时，按独立的现实接触面裂变局部文档，而不是按固定生命周期模板切片。主协调者维护整体底座与跨局部关系，不把全部细节搬回主上下文。
3. **收束期**：局部文档先积累现场事实、耦合边界和已排除的路径。相邻接触面的事实浮出后，再确定跨界契约与实施次序。

## 局部文档如何接回整体

裂变出的局部文档应说明它如何接入整体结构，使接手者能沿整体底座进入本局部，而不必重读全部原始材料：

- **上游地面**：本局部依赖的事实或张力，并链接来源而不重复抄写。
- **接触面与自治权**：本局部负责调查的范围，以及局部可以自行判断的部分。
- **已探明河岸**：接触现实后核实的机制、硬约束和排除掉的路径。
- **跨界输出与未闭合项**：需要相邻局部知道或配合的事实，以及仍缺外部输入或上游裁决的问题。

## 落代码前检查是否假闭合

1. **检查无物强言**：设计中是否有方案骨架、数据结构或步骤尚无对应现实证据？若有，保留为待核实问题，先接触现场。
2. **检查越界代庖**：上层材料是否写死了局部实现细节，以至局部执行者遇到真实阻力仍只能硬凑？若有，退回目标、边界和必要不变量。
3. **检查跨洞闭环**：上游仍有关键未闭合项时，下游是否已经把它当定局？判据是否只测表面，让真实主流程仍未接通也能通过？若是，恢复未闭合关系，并让真实流程接触进入判断。
